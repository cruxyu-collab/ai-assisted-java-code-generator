## 📌 概要 (Overview)

**AI-Assisted Java Code Generator** は、業務システム開発における基本設計書の記述揺れに伴う転記工数および人的ミスを根本から解消するために設計されたバックエンド開発支援エンジンです。

**【開発趣旨】** 本プロジェクトは、株式会社メイテック様への応募にあたり、自律的な生成AIオーケストレーション制御力および決定論的コード生成パイプラインの構築力を客観的に実証するために自作開発した技術デモ（Demo / PoC）です。現在はDTO/ドメインモデルクラス骨格の自動生成に特化していますが、テンプレート拡張によりService/Repository/CRUD全域への適用が可能な疎結合アーキテクチャを採用しています。

Excel形式で作成されたテーブル定義書・項目定義書から、Google Gemini API を用いてクラス名およびフィールド仕様を構造化抽出。**「4段階サニタイズ層」**と**「Pydanticデータ契約層」**による多層防壁を通過させ、万一の抽出不整合時は例外詳細をプロンプトへ自己反映して自動再試行する **Self-Correction（自律的自己修正）エージェント機構** を内装しています。

検証済みのデータのみをパイプラインへ流し込み、Pythonのルールベースジェネレーターにより、コンパイル成立を確証した高品質なJavaデータ構造コードを出力します。

```
[ システム特性 ]
• 責務分離設計: 意味解釈（LLM）と構文出力（Python生成器）を分離し、構文崩れを構造的に排除
• 防御的サニタイズ: Markdownフェンス・末尾カンマ・コメント混入を事前無害化する4段階正規表現前処理
• 自律的自己修正: バリデーション例外をプロンプトへ自己反映し最大3回再試行するエージェント機構
• 決定論的コード生成: 日本語Javadoc自動付与、完全カプセル化（isActive()準拠）のJava 17+ POJO生成
• 高速品質保証: CI/CD環境およびローカルにおいて 20件の自動テストを 0.43秒 で全件パス
```

## 💡 解決する課題とアプローチ (Problem & Approach)

### 【課題】設計書転記に伴う人的ミスとAI直接生成の危険性
業務システムの基本設計書は現場によって記述形式が統一されておらず、手作業でのデータモデルクラス作成はタイポや型間違いの温床となります。一方、生成AIに直接Javaソースコード全体を出力させると、インデント不正、命名規約違反、存在しない型の捏造といったコンパイルエラーが不可避でした。

### 【アプローチ】二元論的分離と自律自己修正ループ
本システムは、「AIには意味解釈のみを任せ、コード生成は絶対確実なルールベースで行う」という役割分担を採用しています。
- **LLM構造化抽出**: Excel設計書から項目論理名・物理名・型・必須フラグのみをJSONとして抽出。
- **データ契約検証**: Pydantic モデルにより、Java識別子規約および許可されたデータ型を厳格検査。
- **Self-Correctionループ**: 抽出データに不整合があれば、バリデーション例外をLLMに自動再注入して自律修正。
- **決定論的レンダリング**: 検証を完全に通過したデータのみを、純粋なPythonロジックで標準Javaコードへ書き出し。
