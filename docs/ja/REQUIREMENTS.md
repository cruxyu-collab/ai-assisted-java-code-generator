# 要件定義仕様書 (System Requirements Specification)

---

## 1. 機能要件 (Functional Requirements)

### FR-01: Excel基本設計書（項目定義書）からの情報抽出
- システムは、openpyxlを通じてExcel形式（.xlsx）の基本設計書・項目定義書を直接読み込まなければならない。
- システムは、Google Gemini API（`gemini-3.8-flash`）を用い、設計書から以下のエンティティ情報を構造化JSONとして抽出しなければならない：
  - クラス名（論理名および物理名）
  - フィールド一覧（変数名、データ型、必須フラグ、日本語論理名）

### FR-02: データバリデーション防壁
- システムは、抽出されたJSONに対して以下のデータ整合性検査を実施し、違反時は処理を安全に中断または自己修正ループへ渡さなければならない：
  - クラス名が PascalCase かつ Java予約語でないこと。
  - フィールド名が lowerCamelCase かつ重複がないこと。
  - Javaデータ型が許可ホワイトリスト（`String`, `int`, `long`, `boolean`）に合致すること。
  - フィールドリストが空でないこと。

### FR-03: Self-Correction 自律修正ループ
- バリデーションエラー検知時、システムは例外詳細（エラー理由・不正項目）をプロンプトにフィードバックとして再注入し、最大3回まで自動再抽出を行わなければならない。

### FR-04: 標準Javaデータ構造・ドメインモデルクラスコード生成
- システムは、検証済みデータに基づき、以下の仕様に準拠したJavaソースコードを出力しなければならない：
  - 各フィールドに対する日本語論理名を含んだJavadocコメントの付与。
  - すべてのフィールドの `private` カプセル化。
  - 標準命名規約（`getXxx()`, boolean型に対する `isActive()`）に準拠したGetter/Setterメソッドの自動生成。
  - 引数なしデフォルトコンストラクタの生成。
  - ファイル保存（`output/<クラス名>.java`）のUTF-8での物理書き出し。

---

## 2. 非機能要件 (Non-Functional Requirements)

### NFR-01: 実行パフォーマンスと品質保証
- 全自動テストスイート（pytest 20件）の実行時間は、ローカル環境において 1.0秒未満（実測値: 約0.43秒）で完了すること。
- コード生成器自体のレンダリング処理時間は 0.1秒未満で完了すること。

### NFR-02: コストおよびインフラ制約
- クラウド利用料は完全無料（Google Gemini API Free Tier枠内）でPoC稼働すること。
- 本番エンタープライズ導入時は、データ学習防止（Zero Retention）が保証されるVertex AI等の有償APIおよび社内プロキシ連携を想定。
