# アーキテクチャ設計決定記録 (Architecture Decision Records)

本ドキュメントは、AI-Assisted Java Code Generatorの設計および実装において下された主要な技術的・構造的意思決定の背景、代替案、および採用理由を記録したものです。

---

## ADR-001: 二元論的分離アーキテクチャの採用（LLMとコードジェネレーターの分離）

- **ステータス**: 承認・実装完了
- **日付**: 2026-10-16
- **コンテキスト**:
  基幹系エンタープライズ開発において、LLMに直接Javaソースコード全体を出力させると、構文エラー、命名規約違反、インデントの乱れ、架空のライブラリのimportなどが発生し、コンパイル成功率が著しく低下する問題があった。
- **決定事項**:
  - LLMの役割を「自然言語の非定型設計書からクラス名および項目定義を抽出する意味解釈」に限定する。
  - Javaソースコードのレンダリングは、Pydantic検証を完全に通過したデータのみを入力とする「決定論的Pythonテンプレートジェネレーター」が担当する。
- **結果・影響**:
  - コンパイルエラーおよび構文エラー発生率 0% を達成。
  - 出力コードの完全なインデント統制およびJavadoc付与の標準化を実現。

## ADR-002: Pydantic v2による厳格なデータ契約とバリデーション防壁

- **ステータス**: 承認・実装完了
- **日付**: 2026-10-16
- **コンテキスト**:
  LLMが出力するJSON構造には、必須キーの欠落、不完全な型指定（例: `datetime` などJava標準外の指定）といったハルシネーションが混入するリスクが存在する。
- **決定事項**:
  `DesignDefinition` モデルを定義し、以下のバリデーション防壁を設ける。
  1. クラス名・フィールド名の正規表現検査（PascalCase / lowerCamelCase）およびJava予約語の抵触検知。
  2. 許可されたJava型（`String`, `int`, `long`, `boolean`）のホワイトリスト厳格制限。
  3. フィールド重複定義の検知および空リストの拒絶。
- **結果・影響**:
  不正データがコード生成層に流入する前にシステムレベルで遮断され、フェイルファスト（Fail-Fast）な安定性を担保。

## ADR-003: 4段階防弾サニタイズパイプライン（Bulletproof Parsing）の導入

- **ステータス**: 承認・実装完了
- **日付**: 2026-10-17
- **コンテキスト**:
  `responseMimeType: "application/json"` を指定しても、モデルの挙動によりMarkdownフェンス（```json）やインラインコメント（`//`）、末尾カンマが混入し、標準 `json.loads` が構文例外（JSONDecodeError）で停止する事象を防止する必要があった。
- **決定事項**:
  JSONデコード前に以下の4段階正規表現パイプラインを必須通過させる。
  1. 境界抽出（最外側の `{` から `}` の切り出し）
  2. インラインコメント（`// ...`）の除去
  3. 末尾カンマ（`,\s*}`）の正規化
  4. 未クォートキーの補正
- **結果・影響**:
  LLMの出力フォーマットの軽微な乱れによるクラッシュを皆無とし、耐障害性を飛躍的に向上。

## ADR-004: Self-Correction（自律的自己修正）エージェントループの実装

- **ステータス**: 承認・実装完了
- **日付**: 2026-10-17
- **コンテキスト**:
  単一のプロンプト送信のみでは、入力設計書が極端に曖昧な場合にバリデーション例外で処理が途絶してしまう。
- **決定事項**:
  Pydanticが検知した具体的なエラーメッセージ（例: フィールド欠落や不正な型名）をフィードバック文字列としてプロンプトに動的付加し、最大3回までLLMに自己修復を試行させるエージェントループを採用。
- **結果・影響**:
  人間の介入を要さずにAIが自律的に正しいスキーマへ出力を収束させることが可能となった。
