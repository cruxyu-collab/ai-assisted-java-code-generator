# Decisions

## D-001 — API보다 로컬 검증을 먼저 구현
- 상태: 확정
- 이유: AI 출력 문제와 검증 코드 문제를 분리하고, API 비용 없이 반복 테스트하기 위함.

## D-002 — Pydantic 2 + pytest
- 상태: 확정
- 이유: 입력 구조와 업무 규칙을 명시적으로 검증하고 자동화하기 위함.

## D-003 — 첫 입력은 JSON
- 상태: 확정
- 이유: 설계서 해석과 데이터 검증을 분리해 첫 단계의 범위를 제한하기 위함.

## D-004 — 지원 자료형은 네 종류로 제한
- 상태: 확정
- 값: String, int, long, boolean
- 이유: 첫 DTO 생성에 필요한 최소 범위. 타입 확장은 테스트를 추가할 때만 허용.

## D-005 — 실제 API 호출은 별도 승인 후 진행
- 상태: 확정
- 이유: API 계정/키가 준비되지 않았으며, 비용과 이용 조건 확인 전 호출하지 않음.
